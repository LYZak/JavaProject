## 目标
- 在 GUI 中增加一个“语言切换开关”，可在中文/英文之间即时切换。
- 切换后无需重启：主窗口标题、菜单、Tab、各面板标题/按钮/提示语同步更新。
- 不引入第三方依赖；优先不新增资源目录（当前项目没有 src/main/resources）。

## 方案选择（推荐）
### A. 纯代码字典（推荐：不新增资源文件）
- 在现有代码中维护 `Language`（ZH/EN）与 `t(key)` 翻译方法（Map）。
- 通过“更新文本”的方式即时切换，不销毁面板、不丢失用户当前输入。
- 优点：不需要新增 `src/main/resources` 与 properties 文件；改动可控。
- 缺点：翻译字符串集中在代码里，不如资源文件易维护（但对课程项目很够用）。

（备选）B. ResourceBundle properties
- 新增 `src/main/resources/i18n/messages_zh_CN.properties` / `messages_en_US.properties`，更标准。
- 需要新增目录与文件，且要处理打包与编码；对当前仓库来说侵入稍高。

## 具体实现计划（按步骤）
### 1) 增加语言开关入口（主窗口菜单）
- 修改 [MainWindow.java](file:///d:/work/JavaProject/src/main/java/com/bigcomp/accesscontrol/gui/MainWindow.java)：
  - 新增 `Language` 菜单：`中文` / `English` 两个单选项（`JRadioButtonMenuItem` + `ButtonGroup`）。
  - 默认语言：根据 `Locale.getDefault()` 自动选择（中文系统默认中文，否则英文）。
  - 切换时触发 `applyLanguage(Language lang)`。

### 2) 建立统一的翻译键体系
- 在主窗口或一个小的 GUI 内部类中定义翻译字典（key -> zh/en）：
  - Window 标题、Menu 文本（File/Help/About/Exit/Refresh/Language）。
  - Tab 标题（Users/Resources/Groups/Profiles/Monitor/Logs/Simulation）。
  - 通用按钮（Add/Delete/Save/Refresh/Clear/Export…）与通用弹窗（Success/Error/Warning/Confirm）。
- 动态文本（含变量，例如删除确认里包含用户名）使用模板：如 `confirm.deleteUser=Are you sure to delete user "{0}"?`。

### 3) 让各面板支持“应用语言”
- 修改每个面板类，增加一个公开方法：`public void applyLanguage(Language lang)`。
- 为保证可更新，需要把“需要翻译的组件引用”保存为字段（例如 JLabel、JButton、TitledBorder、表头列名）。
  - 例如在 [UserManagementPanel.java](file:///d:/work/JavaProject/src/main/java/com/bigcomp/accesscontrol/gui/UserManagementPanel.java)：保存 First Name/Last Name/Gender/Type 标签、按钮文本、表格列名、提示对话框标题/文案。
  - 同理处理资源、组、配置文件、监控、日志、模拟面板。
- `MainWindow.applyLanguage` 中调用每个 tab 组件的 `applyLanguage`，然后更新：
  - Frame title、菜单文本、Tab 标题、状态栏 `Ready | ...` 文案。
  - `SwingUtilities.updateComponentTreeUI(this)` 让 LAF 相关文字/尺寸刷新。

### 4) 表格列名与模型刷新
- 对 JTable 的列名：修改 `DefaultTableModel` 的 `setColumnIdentifiers(...)` 或重设表头值，调用 `getTableHeader().repaint()`。
- 确保语言切换不会清空数据（只变更表头文本）。

### 5) 验证与回归
- 运行 `mvn test` 确保测试仍然全通过。
- 启动 GUI，人工验证：
  - 切换语言后所有 Tab、菜单、按钮、标题、对话框文本即时变化。
  - 切换前后表格数据不丢、输入框内容不丢。
