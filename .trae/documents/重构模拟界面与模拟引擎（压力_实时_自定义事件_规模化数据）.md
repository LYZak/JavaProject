## 目标
- 模拟界面重构为“实时模拟 + 大批量压力模拟”两套可切换模式。
- 界面可配置并注入“自定义事件”（单次/批量/脚本化），能按用户/读卡器/资源/时间执行。
- 支持规模化生成演示数据（用户/徽章/资源/读卡器/资源组/权限），并在生成后自动刷新内存快照。

## 现状与关键问题（已确认）
- EventSimulator 目前仅“固定周期每次 1 个事件”，且内部自行 new DatabaseManager，难以压测与一致性管理：[EventSimulator.java](file:///d:/work/JavaProject/src/main/java/com/bigcomp/accesscontrol/simulation/EventSimulator.java)
- BadgeReader 存在物理节流（3s 冷却）会限制吞吐，不适合压力模式：[BadgeReader.java](file:///d:/work/JavaProject/src/main/java/com/bigcomp/accesscontrol/model/BadgeReader.java)
- EventSimulationPanel 的统计更偏轮询/展示，缺少以 Router 事件驱动的可靠计数与吞吐指标。
- 规模化数据生成目前耦合在 UI 内，后续扩展模板困难。

## 重构方案
### 1) 重新划分模块边界（UI/引擎/数据生成）
- 新增 `SimulationEngine`（统一抽象），提供：start/stop/pause、mode 配置、注入 EventSource、实时指标输出。
- 把当前 `EventSimulator` 重构为 `RealtimeSimulationEngine`（慢速/连续模式）。
- 新增 `StressSimulationEngine`（压力/批量模式）：支持线程数、目标 QPS、每批大小、持续时间、分布策略（固定/突发/阶梯/泊松）。
- 新增 `DemoDataGenerator`（服务类）：把“生成用户/资源/读卡器/组/权限”的逻辑从 UI 下沉，支持多模板。

### 2) 两种模式的行为定义
- **实时模拟**（Slow/Realtime）：保留物理语义（读卡器冷却/资源开关耗时可配置），适合演示真实流程。
- **压力模拟**（Stress）：默认绕开或显著降低物理冷却（可选开关），以“后端处理能力”为主；支持并发与吞吐指标（events/s、拒绝率、平均响应时间等）。

### 3) 自定义事件能力
- 定义统一事件模型 `SimEvent`：
  - 动作：Swipe、UpdateBadge、EnableReader/DisableReader、SetResourceControlled/Uncontrolled、StepTime/SetTime、Wait
  - 目标：用户/徽章、读卡器/资源、时间戳
  - 执行方式：单次、循环（每 N ms）、批量导入（CSV/文本脚本）
- UI 提供“事件编辑器”：选择用户/读卡器/资源、动作、时间与重复策略，一键执行或加入队列。
- 引擎支持“事件队列 + 反馈回调”（基于 Router 的 AccessEventListener/ReaderEventListener）实现按结果分支的脚本。

### 4) 模拟界面重构（EventSimulationPanel → SimulationWorkbench）
- 重做布局为多区块（或子 Tab）：
  - **模式区**：Realtime/Stress 切换 + 参数面板（间隔/QPS/并发/持续时间/是否启用物理冷却等）
  - **自定义事件区**：事件编辑器 + 队列列表 + 执行控制
  - **规模化数据区**：模板选择 + 数量配置（300/400 默认）+ 进度条 + 生成后自动刷新数据
  - **实时反馈区**：读卡器提示流、访问事件流、统计卡片（总数/授权/拒绝/吞吐/延迟）
- 统计改为事件驱动：订阅 Router AccessEventListener/ReaderEventListener，在 Swing 线程安全更新 UI。
- 增加监听生命周期管理：面板 addNotify/removeNotify 中对称注册/反注册 listener，避免重复回调与泄漏。

### 5) 关键缺陷修复与兼容
- 统一实现 `BadgeReader.updateBadge(Badge)`（打通 Update 动作），并让 Router 处理 badgeUpdated 时能携带 oldCode 做内存索引清理（已具备通路）。
- 保持现有监控/日志模块工作方式不变（RealTimeMonitorPanel、LogManager 继续监听 Router）。

## 测试与验收
- 单元测试：
  - Stress 模式在禁用物理冷却时能达到预期事件量级（以计数/时间窗口断言）。
  - 自定义事件：Swipe/Update/时间步进/资源状态切换能够被正确执行并产生事件。
  - 监听生命周期：重复打开/切换面板不产生重复计数。
- 手工验收：
  - 300 用户/400 读卡器一键生成后，实时模式可持续跑并能看到提示流；压力模式可配置吞吐并显示统计指标。
