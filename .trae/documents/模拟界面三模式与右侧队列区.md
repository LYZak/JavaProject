## 需求解读
- 将模拟界面模式扩展为 3 种：实时模拟 / 压力模拟 / 手动模拟。
- 仅在“手动模拟”时，界面最右侧新增一个队列列表区域，用于展示已加入队列的事件内容。

## 现状评估（当前代码）
- 目前模式只有 2 种（Realtime/Stress），通过 `modeCombo` + `modeCard(CardLayout)` 切换。
- “事件队列”UI 当前嵌在 `buildEventControls()` 里（同一行里还包含动作/用户/读卡器/资源/次数以及按钮），队列列表只是一个小的 `JList`。

## 改造方案
### 1) 模式扩展为三种
- 将 `modeCombo` 选项改为三项：实时模拟、压力模拟、手动模拟。
- `modeCard` 增加第三张卡：`Manual`。
  - Realtime 卡：保留当前实时参数（间隔、一致路径、刷新）。
  - Stress 卡：保留当前压力参数。
  - Manual 卡：放置“手动事件参数区”（动作/用户/读卡器/资源/次数 + 加入队列按钮）。

### 2) 右侧增加“最右队列列表”仅手动显示
- 调整右侧布局为“中间主区 + 最右队列区”的水平分割：
  - 中间主区：保留“控制区(含 modeCombo、开始/停止、时间控制、modeCard、数据生成、进度条) + 详情/Feed 分割”。
  - 最右队列区：新增一个独立面板，包含：
    - 队列标题
    - 队列 `JList`（绑定现有 `eventQueueModel`）
    - 运行队列 / 清空队列 / 导入脚本 按钮（从原 eventControls 中迁移过来）
- 在非手动模式：
  - 隐藏该队列区（`setVisible(false)`）或将分割条折叠到最右（保持布局稳定）。

### 3) 行为与按钮启用策略
- “开始/停止”按钮：
  - 实时/压力模式：保持现状。
  - 手动模式：禁用开始/停止（因为手动不启动引擎，只通过队列/单次动作触发）。
- “事件队列执行/导入”等操作：只在手动模式显示在最右队列区。

### 4) 数据模型与刷新
- `eventQueueModel` 改为在构造/初始化时创建一次，避免 UI 重建导致队列丢失。
- `refreshEventCombos()` 逻辑保持不变，仍从用户表/读卡器表刷新下拉框。

### 5) 国际化
- 新增 I18n key：
  - `simw.mode.manual`（手动模拟）
  - `simw.queue.title`（队列列表/事件队列）
  - 如有新增按钮/提示文本，一并补齐中英。

## 验证方式
- 手动验证：
  - 切换三种模式时，modeCard 正确变化。
  - 切到“手动模拟”时，最右队列区出现；其他模式隐藏。
  - 手动模式下：加入队列 → 队列列表实时更新；执行/清空/导入脚本功能不受影响。
- 自动验证：
  - 复用现有测试框架，新增一个轻量 UI 逻辑测试（仅测 model 不丢失/模式切换导致 visible 状态变化的纯方法）。
